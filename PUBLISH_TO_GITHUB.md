# Публикация проекта 205 Доска сборки команд

Имя репозитория — `team-assembly-board`. Профиль — приложение с сервером (FastAPI + SQLite + React, Docker).

## Первый запуск после распаковки

1. Распакуйте ZIP и откройте папку `205-team-assembly-board` в локальном агенте с доступом к файлам и GitHub либо в терминале.
2. Требования к окружению — Docker с Compose v2. Для проверок без контейнера нужны Python 3.12+ и Node.js 22.12+. Команды установки и запуска — `docker compose up -d --build`. Если сборка падает с `certificate verify failed` из-за корпоративного прокси — `docker build --secret id=extra_ca,src=/path/to/ca.pem -t team-assembly-board:local . && docker compose up -d`.
3. Откройте http://127.0.0.1:8205. Для демо войдите кнопкой «Ольга Организаторова» (логин `organizer`, пароль `organizer-demo`). Участники — `p1`…`p8`, пароль `participant-demo`. Ожидаемый результат: в очереди 8 кандидатов, команды «Альфа» и «Бета» по три роли. После пяти назначений сводка показывает «Заполнено мест: 5 из 6» и одну незакрытую роль. Перенос освобождает прежнее место, изменение по устаревшей версии отклоняется с обновлением доски.
4. Команды тестов и сборки — `python3 scripts/container_check.py --restart`. Дальше `cd backend && python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements-dev.txt && python -m pytest`, затем `cd ../frontend && npm ci && npm test && npm run build && npm run e2e:install && npm run e2e`.

## Проверка аккаунта и публикация

Агент проверяет активную сессию GitHub и логин владельца. При работе через GitHub CLI выполните `gh auth status` и `gh api user --jq .login`. Если требуется вход, используйте браузерный вход `gh auth login --web`. Равнозначный вариант — подключённый GitHub с разрешением на создание репозитория и загрузку файлов. Сначала проверьте, что учётные данные относятся к участнику.

Проверьте список файлов для отправки, текущее состояние Git, remote и отсутствие секретов. `.gitignore` исключает `node_modules/`, `frontend/dist/`, `.venv/`, локальную базу `data/` и `*.sqlite3`, результаты тестов и `.env`. Если папка ещё не является Git-репозиторием, создайте его (`git init -b main`) и сделайте первый коммит с корректным описанием и авторством. Не переписывайте историю. Если на GitHub под этим именем уже есть репозиторий, остановитесь перед изменением, объясните, что найдено, и предложите другое имя или согласованный способ обновления. Используйте обычную отправку без принудительной перезаписи.

При новой публикации через CLI используйте `gh repo create OWNER/team-assembly-board --source=. --remote=origin --push --private` или замените `--private` на `--public` по выбору владельца. Перед этим проверьте доступность имени (`gh repo view OWNER/team-assembly-board` должен вернуть «not found») и отсутствие конфликтующего `origin` (`git remote -v`). После отправки проверьте владельца, наличие ветки `main` и файлов и откройте полученную ссылку с нужными правами доступа.

## Развёртывание этой версии

**Проверено — локальный запуск.** `docker compose up -d --build` → http://127.0.0.1:8205. Демо-доступ работает только с этого компьютера: порт привязан к `127.0.0.1`, демо-входы включаются `DEMO_MODE=1`.

**Интернет-развёртывание (не выполнялось, требует выбора и авторизации хостинга владельцем).** GitHub Pages не подходит: ему нужен сервер для Python-контейнера. Требования к хостингу:

| Требование | Как выполнить |
|---|---|
| Контейнер | образ из `Dockerfile`, слушает порт 8000, команда по умолчанию `uvicorn app.main:app --host 0.0.0.0 --port 8000 --proxy-headers` |
| Постоянный диск для SQLite | том, смонтированный в `/data` (база `/data/team-board.sqlite3`). Один экземпляр приложения: SQLite не рассчитан на несколько реплик с общим диском |
| HTTPS | терминирует хостинг или обратный прокси. Выставьте `COOKIE_SECURE=1`, чтобы cookie сессии уходили только по HTTPS |
| Переменные среды | `DEMO_MODE=0` и `SEED_DEMO=0` для публичной версии (без демо-входов, `/api/demo/*` и демо-паролей). `DB_PATH` и `STATIC_DIR` уже заданы в образе |
| Учётные записи | регистрации через интерфейс в этой версии нет. Создавайте пользователей командой `python -m app.users add <логин> --role organizer|participant --name "Имя"` (пароль спрашивается скрыто, от 8 символов), смена пароля — `python -m app.users passwd <логин>`. Демо-пароли из `seed.py` в публичной версии использовать нельзя |
| Миграции | применяются автоматически при старте контейнера (`schema_migrations`). Отдельной команды не нужно |
| Проверка готовности | `GET /api/health` → `{"status":"ok"}`. Этот же адрес использует `HEALTHCHECK` образа |
| Резервная копия | регулярная копия файла базы: `sqlite3 /data/team-board.sqlite3 ".backup /data/backup-$(date +%F).sqlite3"` или снимок тома хостинга. В WAL-режиме не копируйте файл базы простым `cp` на работающем сервере |

В результате должны быть ссылка на репозиторий с владельцем и видимостью и один из двух результатов по демо: проверенная ссылка на развёрнутый сайт либо подтверждённый локальный адрес с командой запуска.

# Приёмка 205 · team-assembly-board

## Как повторить проверки

```bash
docker compose up -d --build                      # http://127.0.0.1:8205, дождаться healthy
python3 scripts/container_check.py --restart      # готовность, роли, 8 параллельных назначений, перезапуск

cd backend && python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest                                  # 24 теста; замер — python -m pytest tests/test_perf.py -s

cd ../frontend && npm ci
npm test                                          # 3 теста Vitest
npm run build
npm run e2e:install && npm run e2e                # 15 сквозных тестов против контейнера (+1 замер, пропускается без синтетики)
docker compose exec app python -m app.synthetic 100 && npx playwright test e2e/perf.spec.ts
npm run e2e:local                                 # те же тесты без Docker (uvicorn из backend/.venv)
```

| Компонент | Версия |

| Образы | `python:3.12-slim`, `node:22-alpine` |
| Python (тесты на хосте) / в образе | 3.13.18 / 3.12 |
| FastAPI / Starlette / Pydantic / uvicorn | 0.165.0 / 1.10.0 / 2.14.4 / 0.54.0 |

**Особенность окружения.** Песочница перехватывает исходящий TLS прокси с собственным корневым сертификатом, поэтому `docker compose up -d --build` здесь падал на `pip install` с `certificate verify failed`. Dockerfile получил необязательный секрет сборки `extra_ca`, и в песочнице образ собирался так: `docker build --secret id=extra_ca,src=<ca-bundle> -t team-assembly-board:local . && docker compose up -d`. Это и есть путь README для корпоративного прокси. Без секрета сборка не меняется.

## Раунд 1. Правила и полнота продукта

**Что проверялось.** Модель ТЗ (набор, профиль, отклик, команда, слот роли, назначение), вместимость слотов, уникальность назначения в наборе, права организатора, фильтр навыков, сводка незакрытых ролей, итог для участника, контракт API (`GET /board`, `POST /applications`, `PUT`/`DELETE /assignment` с версией, актуальная доска при конфликте), приёмочный сценарий: 8 кандидатов, две команды, одна роль открыта, перенос, повторное назначение запрещено.

**Диагностика.** Модельный тест `test_model.py`: 400 случайных операций (назначение, перенос, возврат, изменение вместимости, 15 % — с устаревшей версией). После каждой операции сервер сверяется с моделью в памяти. Распределение веток в прогоне: 192 изменения, 73 отказа «занято», 41 конфликт версии, 42 повтора без изменений, 48 изменений вместимости, 4 отказа «ниже занятого».

| Найдено | Исправление |
|---|---|
| Сводка «незакрытые роли» перечисляла слоты вперемешку по командам (Альфа — Backend, Бета — Backend, Альфа — Frontend…): сортировка шла по позиции роли без учёта порядка команд | сортировка `t.position, t.id, s.position, s.id` |

**Повторная проверка.** Модельный тест 1/1, весь pytest — 18/18 на тот момент.

## Раунд 2. Ошибки, данные и восстановление

**Что проверялось.** Роли и права, параллельные назначения, повтор действия, перезапуск сервера и контейнера, обрыв сети и истёкшая сессия в интерфейсе.

| Проверка | Результат до исправления |
|---|---|
| 8 параллельных запросов в слот вместимостью 1 (uvicorn и контейнер) | ровно 1 × 200, 7 × 409 `slot_full` — ок |
| Одна карточка одновременно в 6 слотов с одной версией | 1 × 200, 5 × 409 `version_conflict` — ок |
| Повтор `PUT` после потерянного ответа (та же версия, тот же слот) | **409 `version_conflict`**, хотя карточка уже на месте |
| Чужой организатор: доска, назначение, закрытие набора | 403 — ок |
| Перезапуск uvicorn на той же базе | миграции не повторяются, сид не дублирует, состав сохранён — ок |
| `docker compose restart`, `down` + `up`, повторный `app.seed`, `down -v` | заполнено 1 → 1 → 1 → 1 → 0 (только `down -v` сбрасывает) — ок |
| Обрыв сети при назначении в интерфейсе | «Сервер недоступен…», карточка не зависает, повтор работает — ок |
| Истёкшая сессия (удалены cookie) | **интерфейс оставался на доске** с ошибкой «Нужно войти» |

**Исправления.**
1. Идемпотентный повтор: если карточка уже в целевом слоте (или уже в очереди), ответ 200 `changed=false` при любой версии. Перенос в другое место по устаревшей версии — по-прежнему 409. Модельный тест обновлён под правило.
2. Любой 401 на действие отправляет событие `auth-lost`: приложение показывает вход с сообщением «Сессия закончилась — войдите снова».

**Повторная проверка.** pytest — 21/21, e2e — 9/9 на тот момент, `container_check.py --restart` — все шаги ok.

## Раунд 4. Производительность и качество реализации

**Что проверялось.** Набор из 100 синтетических откликов (`python -m app.synthetic 100`: 10 команд × 5 ролей × 2 места), настоящий uvicorn. Загрузка доски, назначение, вход, список наборов, профиль сборки доски (cProfile), интерфейс в Chromium.

**Сервер (50 запросов на метрику, мс).**

| Шаг | p50 | p95 | Комментарий |
|---|---|---|---|
| Вход (`POST /auth/login`) | 23,0–23,7 | 26,8–39,1 | самый медленный одиночный запрос: PBKDF2 120 000 итераций, намеренно |
| Доска (`GET /board`), 31 063 байта | 5,6–5,7 | 7,3–7,7 | в сборке доски половина времени — разбор JSON навыков и ролей (200 вызовов `json.loads`) |
| Назначение (`PUT /assignment`) с доской в ответе | 7,7–7,9 | 10,1–11,0 | |
| Список наборов | 3,7–3,9 | 4,8–5,1 | |
| **Опрос неизменной доски — до** | 5,7 | 7,7 | каждые 5 с полные 31 КБ на каждую открытую вкладку |
| **Опрос неизменной доски — после** | 3,1 | 4,3 | 304 без тела, доска не собирается |

**Исправление.** `ETag` по `board_version` и `Cache-Control: private, no-cache`. Браузер сам перепроверяет доску (`If-None-Match`), сервер отвечает 304 без сборки. Клиентский код не менялся. В браузере 304 подтверждены сырыми кодами CDP: `page.on('response')` показывает такой ответ как 200 из кэша, на этом я сначала ошибся.

**Интерфейс (100 карточек, 50 слотов).** 1 940 элементов DOM. Переключение на набор — 92–112 мс, худшее событие 24–32 мс. Назначение через меню — худшее событие 72–88 мс. Длинных задач (> 50 мс) нет, опрос — 304.

**Повторная проверка.** `test_perf.py` (пороги p95 доски < 200 мс, назначения < 300 мс) и `perf.spec.ts` (100 карточек, все опросы 304) — зелёные. pytest — 23/23.

## Известные ограничения

- В тестах pytest Starlette 1.10 выдаёт предупреждение `StarletteDeprecationWarning` о `httpx` в `TestClient` (рекомендует пакет `httpx2`). На работу сервера не влияет, тесты проходят.
- Сквозные тесты сбрасывают демо через `/api/demo/reset`, а он удаляет все наборы, кроме демо: не запускайте их на базе с реальными данными.
- Перетаскивание проверено в Chromium (Playwright). На сенсорных экранах HTML5 drag-and-drop не работает — там назначают через меню «Назначить…».
- Интернет-развёртывание не выполнялось: требования к хостингу описаны в `PUBLISH_TO_GITHUB.md`.
- Проверки проводились в Chromium. Firefox и Safari не тестировались.

# Карточка продукта

| Поле | Значение |
|---|---|
| Номер | 205 |
| Название | Доска сборки команд |
| Репозиторий | `team-assembly-board` |
| Профиль | приложение с сервером: FastAPI + SQLite + React, Docker Compose |
| Версия | 1.0.0 (ночной пилот, 2026-11-20) |

## Аудитория и задача

Организаторы хакатонов, проектных интенсивов и студенческих курсов, которым нужно собрать из откликнувшихся людей команды с заданными ролями (backend, frontend, дизайн, аналитик и т. п.). Участникам нужно понятно подать заявку и узнать, куда их распределили.

## Сценарий

1. Организатор открывает набор, создаёт команды и роли с вместимостью.
2. Участники входят и подают карточку: имя, навыки, интересы, желаемые роли.
3. Организатор видит очередь кандидатов и колонки команд. Фильтрует очередь по навыкам и переносит карточки в слоты ролей: перетаскиванием или через меню «Назначить…» с клавиатуры. Сводка показывает, какие роли ещё не закрыты.
4. Сервер не даёт переполнить слот и назначить человека дважды. При одновременной работе двух организаторов конфликт возвращает актуальную доску.
5. Участник видит итог: команда и роль или «в очереди». Организатор выгружает состав в CSV и закрывает набор.

## Функции версии 1.0

- Роли «организатор» и «участник», вход по логину и паролю, сессии в HttpOnly-cookie, демо-входы в демо-режиме.
- Наборы: создание, открытие и закрытие. Команды и слоты ролей с вместимостью: добавление, изменение (не ниже занятого), удаление пустых.
- Отклики: один на человека в наборе, проверка полей, желаемые роли только из ролей набора.
- Доска: очередь с фильтром по навыкам и поиском, колонки команд, слоты с «занято N из M», перетаскивание, клавиатурное меню назначения (желаемые роли сверху, занятые недоступны), «В очередь».
- Назначение и перенос — одна транзакция с проверкой вместимости и версии назначения. Конфликт возвращает 409 и актуальную доску. Повтор уже выполненного действия безопасен.
- Сводка незакрытых ролей, автообновление доски каждые 5 с с ETag/304, страница результата участника с автообновлением.
- Экспорт состава в CSV (с защитой от формул), консольное управление пользователями, демо-сид, синтетика на 100 откликов.
- Docker: многоэтапная сборка, том для SQLite, проверка готовности, миграции при старте.

## Практический результат

За несколько минут собран состав команд, в котором гарантированно нет переполненных ролей и дублей людей. Видно, какие роли остались открытыми. Участники узнают итог сами, без рассылки.

## Границы текущей версии

- Нет самостоятельной регистрации и восстановления пароля: учётные записи создаёт администратор (`python -m app.users`) или сид.
- Участник не может изменить или отозвать поданный отклик.
- Нет уведомлений по почте и в мессенджерах: итог виден на странице участника.
- Один экземпляр сервера (SQLite). Горизонтальное масштабирование потребует другой СУБД.
- Изменения от других организаторов приходят опросом раз в 5 с, без WebSocket.

# 205 · Доска сборки команд

`team-assembly-board` — веб-приложение с сервером. Организатор открывает набор и задаёт роли в командах с вместимостью. Участники подают карточки с навыками, интересами и желаемыми ролями. На доске организатор переносит карточки из очереди в слоты команд мышью или через меню с клавиатуры. Сводка показывает незакрытые роли, а участник видит итог своего назначения.

Стек: React + TypeScript + Vite (интерфейс), FastAPI + SQLite (сервер). Всё упаковано в один Docker-контейнер с одним портом.

## Первый запуск (Docker)

Требования: Docker с Compose v2.

```bash
docker compose up -d --build
```

Откройте **http://127.0.0.1:8205**. Порт опубликован только на `127.0.0.1`, поэтому доска доступна лишь с этого компьютера. При первом старте применяются миграции и создаётся демо-набор. Готовность — `curl http://127.0.0.1:8205/api/health` → `{"status":"ok",…}`, контейнер становится `healthy`.

| Роль | Логин | Пароль |
|---|---|---|
| Организатор | `organizer` | `organizer-demo` |
| Участники | `p1` … `p8` | `participant-demo` |

На экране входа есть кнопки демо-входа (только при `DEMO_MODE=1`).

Демоданные:

```bash
docker compose exec app python -m app.seed            # создать, если нет (повторный запуск не дублирует)
docker compose exec app python -m app.seed --reset    # вернуть демо к исходному виду: все в очереди
docker compose exec app python -m app.synthetic 100   # набор «Синтетика 100» для замеров
```

Данные хранятся в томе `board-data` (`/data/team-board.sqlite3`) и переживают `docker compose restart` и `docker compose down` + `up`. Полный сброс — `docker compose down -v`.

Если сборка идёт через корпоративный прокси с собственным корневым сертификатом (ошибка `certificate verify failed` на `npm ci` или `pip install`), передайте сертификат необязательным секретом сборки:

```bash
docker build --secret id=extra_ca,src=/path/to/ca.pem -t team-assembly-board:local .
docker compose up -d
```

## Демонстрационный сценарий (по ТЗ)

1. Войдите как **Ольга Организаторова**. В очереди 8 кандидатов, команды «Альфа» и «Бета», по три роли с одним местом.
2. Соберите две команды и оставьте одну роль открытой. Например: Антон → Альфа/Backend, Вика → Альфа/Frontend, Денис → Альфа/Дизайн, Илья → Бета/Backend, Лена → Бета/Frontend. Перетащите карточку на слот или нажмите «Назначить…», выберите «Команда — Роль» и нажмите «Назначить».
3. Сводка: «Заполнено мест: 5 из 6», «Незакрытые роли: Бета — Аналитик».
4. Перенесите участника: «Перенести…» у Антона → «Бета — Аналитик». Альфа/Backend освобождается.
5. Повторное назначение того же человека по устаревшим данным запрещено. Откройте доску во второй вкладке до переноса и попробуйте там изменить Антона: появится «Карточку уже изменили…», и доска обновится. Занятое место недоступно в меню, а перетаскивание на него даёт «Место … уже занято».
6. Войдите как участник (`p1`): виден итог «Вы в команде …» или «Ваша заявка в очереди». Доска участнику недоступна.
7. «Экспорт состава CSV» — состав по командам, свободные места и очередь.

## Проверки

```bash
# Сервер: pytest (API, правила, модельный тест, параллельные запросы на настоящем uvicorn, перезапуск, замер)
cd backend
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest                 # PERF205 печатается с флагом -s

# Интерфейс: Vitest, сборка, сквозные тесты Playwright против запущенного контейнера
cd ../frontend
npm ci
npm test
npm run build
npm run e2e:install              # один раз: Chromium
npm run e2e                      # против http://127.0.0.1:8205 (docker compose up -d)
# замер UI на 100 откликах: docker compose exec app python -m app.synthetic 100 && npx playwright test e2e/perf.spec.ts

# Контейнер целиком: готовность, обе роли, 8 параллельных назначений на одно место, перезапуск
cd ..
python3 scripts/container_check.py --restart
```

Сквозные тесты сбрасывают демо-набор через `/api/demo/reset`: этот вызов удаляет все наборы, кроме демо. Не запускайте их на базе с настоящими данными.

## Запуск без Docker (разработка)

```bash
cd backend && . .venv/bin/activate
DEMO_MODE=1 SEED_DEMO=1 uvicorn app.main:app --port 8000 --reload     # API на :8000, база ./data/team-board.sqlite3
cd ../frontend && npm run dev                                           # http://localhost:5205, /api проксируется на :8000
```

Собранный интерфейс без Vite: `npm run build`, затем запуск сервера с `STATIC_DIR=../frontend/dist` → http://127.0.0.1:8000. Сквозные тесты без Docker: `npm run e2e:local` (поднимает uvicorn на :8215 с временной базой, нужен собранный `dist/`).

## Учётные записи

Демо-пользователи создаются сидом. Свои — командой (пароль спрашивается скрыто):

```bash
docker compose exec -it app python -m app.users add maria --role organizer --name "Мария Иванова"
docker compose exec -it app python -m app.users passwd maria
docker compose exec app python -m app.users list
```

## Переменные окружения

См. `.env.example`: `APP_PORT` (по умолчанию 8205), `DEMO_MODE`, `SEED_DEMO`, `COOKIE_SECURE`. Внутри контейнера — `DB_PATH=/data/team-board.sqlite3`, `STATIC_DIR=/app/static`. Секретов нет: сессии — случайные токены в базе, пароли хранятся как PBKDF2-SHA256.

## Где что лежит

| Путь | Назначение |
|---|---|
| `backend/app/main.py` | маршруты API, сессии, проверка прав, ETag доски, раздача интерфейса |
| `backend/app/service.py` | правила: доска, отклики, назначение и перенос в транзакции, структура набора, CSV |
| `backend/app/db.py`, `backend/app/migrations/` | SQLite, транзакции `BEGIN IMMEDIATE`, миграции |
| `backend/app/seed.py`, `backend/app/synthetic.py` | демоданные и синтетика |
| `backend/tests/` | pytest |
| `frontend/src/` | интерфейс: вход, доска организатора, меню назначения, настройка, страница участника |
| `frontend/e2e/` | Playwright |
| `scripts/container_check.py` | проверка запущенного контейнера |
| `Dockerfile`, `compose.yaml`, `.env.example` | контейнер и запуск |
| `docs/` | карточка, архитектура, приёмка, ассеты, исходное ТЗ |
